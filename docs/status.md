## 設計上の判断と理由

- **PWA にした**: 解析も保存もブラウザ内で完結するのでサーバーが要らない。
  Discord bot 版も作ったが、常駐先 (無料の VM) の管理が必要で手間なのでやめた (`bot/` は未使用、リポジトリ対象外)。
- **解析はローカルで行う**: 外部 API を使わない。文字認識は tesseract.js のみ。
- **記録は全部残す**: 定数の改定や仕様変更があっても計算し直せるように、B50 圏外の記録も捨てない。B50 は毎回計算する。
- **譜面は曲名に頼らず特定する**: リザルト画面の曲名はキャラの絵で隠れることが多い。
  代わりに「PURE+FAR+LOST = ノーツ数」と「スコア = 10M × (PURE + FAR/2) / ノーツ数 + 大PURE数」で候補を絞り、
  曲名のあいまい一致は順位づけにだけ使う。判定数は読み間違えやすい桁の別候補も試し、LOST が隠れていればノーツ数から逆算する。
- **公式の素材は使わない**: ロゴ・キャラクター・背景・ジャケットを同梱しない。
  ジャケットはユーザー自身のスクショから切り出してブラウザ内にだけ保存する (配布しない)。
- **譜面は `songId:difficulty` で持つ**: Tachi 側の ID 変更に影響されないように、ゲーム内の曲 ID を使う。

## データの更新

新曲の追加や定数の改定があったとき:

```sh
cd web
curl -sL -o ../data/tachi/charts-arcaea.json https://raw.githubusercontent.com/zkldi/Tachi/main/db/seeds/charts-arcaea.json
curl -sL -o ../data/tachi/songs-arcaea.json  https://raw.githubusercontent.com/zkldi/Tachi/main/db/seeds/songs-arcaea.json
npm run data     # public/data/charts.json を作り直す
python3 ../scripts/verify.py   # 手元の画像と食い違う定数がないか確認
```

食い違いが出たら、画像から逆算した値を `data/overrides.csv` に書く (Tachi も wiki も間違っていることがある)。
